# Общий отчет по гостевому UI (неавторизованный пользователь)

Дата: **2026-03-26**

## Цель

Обновить аудит и подготовить основу для плана рефакторинга с фокусом на:

1. удаление **совсем лишнего** кода (не используется в текущей архитектуре гостевого сценария);
2. удаление дублирующего функционала;
3. удаление лишнего кода/ассетов для неавторизованных посетителей.

Покрытие:
- `learning-articles`;
- `learning-paths`;
- `tests`;
- `moi-oblasti-znanij`;
- `achievements`.

---

## 1) Executive summary (что критично)

### Критично (P1)

1. В `learning-paths` для гостя в HTML рендерится модалка **«Создать траекторию»** (служебный UI), хотя кнопка создания скрыта.
2. `tsScripts` подключает глобально «все модули спринтов» на любой странице, включая гостевые экраны, где они не используются.
3. На гостевых страницах есть дублирование инфраструктуры (`csrf-helper.js` + локальный inline `tsApiRequest`, дубли `meta[name="csrf-token"]` в ряде сниппетов).

### Важно (P2)

4. На `tests` для гостя рендерится скрытый блок редактора вопросов и грузятся editor-зависимости (Quill/DOMPurify + shared editor JS), хотя гостевой сценарий — только просмотр/запуск доступных тестов.
5. На `moi-oblasti-znanij` гость видит только alert авторизации, но при этом грузится тяжелый общий JS-пакет из `tsScripts`.

---

## 2) Детализация по страницам (гость)

## A. `learning-articles`

### Нужное
- базовый layout/CSS;
- Bootstrap JS;
- контент сниппета `learningMaterialsTemplate`.

### Лишнее/избыточное
- глобальные модули из `tsScripts`, не относящиеся к странице;
- global inline-логика `initLearningPathStepPanel()` (в обычном гостевом сценарии не активируется);
- дубли API-helper логики относительно `csrf-helper.js`.

---

## B. `learning-paths`

### Нужное
- список траекторий и фильтры для публичного просмотра.

### Лишнее/проблемное
1. **Служебная модалка в гостевом DOM**: `renderPathModal()` добавляется всегда в list-режиме.
2. Дубли CSRF meta (`tsHead` + `$csrfMeta` из сниппета).
3. Глобальные нерелевантные JS из `tsScripts`.

---

## C. `tests`

### Нужное для гостя
- карточки тестов, категории, поиск, кнопки запуска гостевых тестов (где разрешено).

### Совсем лишнее для гостевого сценария (удалять/не рендерить)
1. `#questions-editor-view` (скрытая зона редактора вопросов) — это административный сценарий, не гостевой.
2. Quill (`quill.min.js`, `quill.snow.css`) и DOMPurify для редактора вопросов — не нужны гостю.
3. `question-list-shared.js`, `test-settings-shared.js` — модули редактора/настроек, не нужны гостю.
4. Дублирующее подключение `csrf-helper.js` (уже есть в `tsScripts`, плюс повторно подключается сниппетом страницы тестов).

### Избыточно по текущей архитектуре
- загрузка в `tsScripts` unrelated-модулей (`knowledge-areas.js`, `learning-paths.js`, `analytics.js`, `certificates.js` и т.д.) на странице тестов.

---

## D. `moi-oblasti-znanij`

### Фактический гостевой сценарий
- страница возвращает alert: «Требуется авторизация».

### Совсем лишнее
- почти весь JS из `tsScripts` (для гостя здесь нет интерактива, кроме базовой навигации/Bootstrap).
- любые feature-модули знаний (в т.ч. `knowledge-areas.js`) не должны загружаться до авторизации.

---

## E. `achievements` (лидерборд)

### Нужное
- серверно отрисованный контент таблицы лидеров.

### Совсем лишнее
- большая часть feature JS из `tsScripts` (модули тестов/траекторий/сертификатов/аналитики и т.д.), если на странице нет соответствующих контейнеров.

---

## 3) Матрица «оставить / убрать» для гостя

### Оставить в базовом guest-bundle
1. Bootstrap bundle;
2. минимальный shared JS (только реально общий, без feature-логики);
3. `csrf-helper.js` **только если на странице есть реальные API-вызовы в гостевом режиме**.

### Убрать из global-by-default
1. `mytests.js`
2. `knowledge-areas.js`
3. `category-permissions.js`
4. `learning-paths.js`
5. `special-question-types.js`
6. `gamification.js`
7. `analytics.js`
8. `certificates.js`
9. глобальный inline `tsApiRequest` (дублирует helper)
10. глобальный inline `initLearningPathStepPanel()`

### Убрать точечно на `tests` для гостя
1. `#questions-editor-view` markup;
2. Quill + DOMPurify;
3. `question-list-shared.js`;
4. `test-settings-shared.js`.

---

## 4) Дубли функционала (что нужно почистить)

1. **CSRF helper duplication**:
   - общий `csrf-helper.js`;
   - локальный `tsApiRequest`/`getCSRFToken` в inline script.
   - Целевое состояние: единая точка через `window.TestSystemCSRF`.

2. **CSRF meta duplication**:
   - токен в `tsHead` + повторная вставка из сниппетов (`learningPaths`, `categoriesAndTests`, `learningMaterialsTemplate`).
   - Целевое состояние: один meta в `<head>`.

3. **UI duplication по ролям**:
   - служебные модалки/редакторы рендерятся даже там, где у гостя нет прав.
   - Целевое состояние: рендер по capability-флагам (`$canCreate`, `$canManage`, `$isAuthenticated`).

---

## 5) Конкретные действия для плана доработок

### P1 (быстрый эффект)
1. В `learningPaths::renderPathsList()` рендерить `renderPathModal()` только при `$canCreate`.
2. На `tests` обернуть рендер `#questions-editor-view` и подключение Quill/DOMPurify/shared editor JS в проверку прав управления.
3. Удалить дубли `csrf-helper.js` на `tests` (оставить один источник).

### P2 (архитектурно)
4. Разделить `tsScripts` на:
   - `base` (минимум для всех);
   - `feature` (модули по странице/роли).
5. Перенести `initLearningPathStepPanel` из общего inline-кода в профильный модуль траекторий.

### P3 (финализация)
6. Убрать дубли CSRF meta из сниппетов, если уже есть токен в `tsHead`.
7. Зафиксировать smoke-checklist гостевых страниц (DOM без служебных модалок/редакторов).

---

## 6) Definition of Done для рефакторинга

1. Гость не получает в DOM служебные формы/модалки создания/редактирования.
2. На гостевых страницах грузится только релевантный JS-набор.
3. На странице ровно один `meta[name="csrf-token"]`.
4. Нет дублирующих helper-реализаций API/CSRF.
5. Сохранены рабочие сценарии admin/expert/authenticated user.

---

## 7) Итог

На текущем наборе страниц основной перерасход возникает не из-за одного файла, а из-за архитектуры «global scripts for all». Для гостя это приводит к:
- лишнему весу страницы;
- лишнему DOM служебных элементов;
- дублированию инфраструктурного кода.

Приоритет для немедленного исправления: **убрать рендер служебных модалок/редакторов для гостя и отключить загрузку feature JS, не используемого в гостевом сценарии**.
