# Аудит HTML/JS страницы `learning-articles` для неавторизованного пользователя

Дата аудита: **2026-03-26**

## Контекст

Проверялся код страницы, которую видит **гость** (неавторизованный пользователь), на шаблоне `TestSystem.tpl` с чанками `tsHead`, `tsHeader`, `tsScripts` и сниппетом `learningMaterialsTemplate`.

Цель аудита:

1. Отделить **обязательный код** от **лишнего** на гостевой версии страницы.
2. Ответить на вопросы:
   - зачем подключается `gamification.js`;
   - зачем отображается/инициализируется код завершения шага траектории обучения.

## 2) Что на гостевой странице сейчас лишнее или спорное

Ниже перечислено, что подключается глобально через `tsScripts`, но на `learning-articles` для гостя практически не нужно.

### Избыточные/условно лишние JS-файлы для гостя

1. `mytests.js`
2. `knowledge-areas.js`
3. `category-permissions.js`
4. `learning-paths.js`
5. `special-question-types.js`
6. `gamification.js`
7. `analytics.js`
8. `certificates.js`

**Почему лишние для гостя `learning-articles`:**
- почти все эти модули инициализируются только при наличии специальных контейнеров (например, `#my-tests-container`, `#knowledge-areas-container`, `#gamification-profile-container` и т.д.);
- на странице учебника таких контейнеров нет, поэтому реальные бизнес-сценарии не запускаются;
- но браузер всё равно тратит ресурсы на скачивание/парсинг/компиляцию JS.

### Частично нужный модуль

- `notifications.js` — на госте фактически не выполняет бизнес-логику (нет колокольчика/контейнеров уведомлений для гостя), но остается безопасным из-за guard-проверок.
- С практической точки зрения для гостя его тоже можно подключать условно.

## 3) Ответ на ваш вопрос про `<!-- Sprint 13: Геймификация -->`

```html
<script src="/assets/components/testsystem/js/gamification.js"></script>
```

На странице гостя `learning-articles` этот файл подключается из-за **глобального чанка `tsScripts`**, а не потому что именно здесь нужна геймификация.

Фактически модуль `gamification.js` активируется только если есть целевые контейнеры (`#gamification-profile-container`, `#gamification-header-widget`, `#achievements-container`, `#leaderboard-container`). На гостевом учебнике их нет.

**Вывод:** для гостя на этой странице подключение `gamification.js` — **технически лишняя нагрузка** (можно убрать через условную загрузку по роуту/по наличию контейнера).

## 4) Ответ на вопрос про код прохождения шагов траектории

В `tsScripts` всегда вызывается:

- `initLearningPathStepPanel()` на `DOMContentLoaded`.

Далее функция сразу проверяет контекст:
- параметры `?path=...&step=...`;
- что это не `/learning-paths`;
- что нет контейнеров страницы траекторий.

Только при совпадении условий создаётся fallback-панель «Шаг траектории» с кнопкой завершения шага.

**Зачем это сделано:**
- пользователь может открыть контент шага траектории (например, материал/тест) вне основной страницы траекторий;
- панель даёт способ завершить шаг и вернуться в траекторию.

**Для гостя на обычном `learning-articles` без `path/step` параметров этот код не нужен по сценарию**, но он просто выполняет проверки и выходит.

## 5) Проблемные места в текущем HTML/шаблонах

1. **Дублирование CSRF meta-тега**.
   - В `<head>` токен уже выводится через `csrfToken`.
   - В `learningMaterialsTemplate` токен может выводиться повторно в контенте.
   - Это не критично, но создает шум и риск рассинхронизации ожиданий в JS.

2. **Глобальный helper `tsApiRequest` в `tsScripts` дублирует ответственность `csrf-helper.js`**.
   - По `DEVELOPMENT_RULES.md` для новых/изменяемых модулей должен использоваться единый `window.TestSystemCSRF.apiCall(...)`.

3. **Глобальные «эффекты для всех карточек»** в `tsScripts`:
   - принудительная анимация всех `.card` через `IntersectionObserver`;
   - для контентных страниц это спорно (визуальный шум), и частично конфликтует с принципом «спокойный интерфейс» из `STYLE_GUIDE.md`.

4. **Подключение тяжёлого общего набора JS на каждом экране**.
   - В том числе для страниц, где эти модули не нужны (как гостевой учебник).

## 7) Рекомендации (безопасный план оптимизации)

1. Перевести `tsScripts` на **условную загрузку модулей по странице**:
   - либо через `$_modx->resource.id` / alias,
   - либо через дата-атрибут режима страницы (`data-page="learning-articles"`).

2. Вынести код fallback-панели шага траектории из общего inline-блока в `learning-paths.js` и запускать только в релевантном контексте.

3. Удалить дублирующий `tsApiRequest` из `tsScripts`, использовать единый helper (`window.TestSystemCSRF`).

4. Перенести/ограничить общую анимацию `.card`:
   - либо отключить на контентных страницах,
   - либо запускать только при явном CSS-флаге страницы.

5. Убрать дублирование CSRF meta-тега: оставить единый источник в `<head>`.

## 8) Итог

Для гостя страница сейчас работает, но грузит заметно больше JS, чем нужно. Основной технический долг — глобальный чанк `tsScripts`, который подключает модули всех спринтов независимо от контекста.

**Кратко:**
- `gamification.js` на гостевом учебнике почти наверняка лишний;
- код завершения шага траектории нужен как fallback-сценарий, но его место не в глобальном скрипте, а в профильном модуле с условной инициализацией.
