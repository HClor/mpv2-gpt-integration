# Системные настройки MODX для LMS

Этот документ описывает системные настройки, которые необходимо создать в MODX для корректной работы системы тестирования.

---

## 📋 Обязательные настройки

### 1. `lms.test_page` - Страница запуска тестов

**Назначение:** ID ресурса со сниппетом `[[!testRunner]]` для отображения и прохождения тестов.

**Тип:** Number (Integer)

**Значение:** ID ресурса (например, `155`)

**Использование:**
- Формирование URL'ов для перехода к тестам из списков
- Отображение тестов с параметром `?test_id=N`

**Пример URL:** `https://ваш-сайт.ru/test-runner?test_id=42`

**Где используется:**
- `UrlHelper::addUrlsToTests()` - построение URL'ов в списках тестов
- `myTests.php`, `categoriesAndTests.php` - ссылки на тесты

---

### 2. `lms.create_test_page` - Страница создания теста

**Назначение:** ID ресурса со сниппетом `[[!addTestForm]]` для создания новых тестов.

**Тип:** Number (Integer)

**Значение:** ID ресурса (например, `36`)

**Использование:**
- Кнопка "Создать тест" на странице "Мои тесты"
- Перенаправление после создания теста

**Пример URL:** `https://ваш-сайт.ru/create-test`

**Где используется:**
- `myTests.php` - кнопка "Создать тест"

---

## 🔧 Опциональные настройки

### 3. `lms.public_test_page` - Публичная страница теста

**Назначение:** ID ресурса для отображения публичных тестов по slug.

**Тип:** Number (Integer)

**Значение:** ID ресурса (например, `160`)

**Использование:**
- Построение публичных URL'ов с slug (например, `/test/javascript-basics`)
- SEO-дружественные ссылки

**Пример URL:** `https://ваш-сайт.ru/public-test?slug=javascript-basics`

**Где используется:**
- `UrlHelper::buildPublicTestUrl()` - построение публичных URL'ов
- `TestService.php` - создание публичных тестов

---

### 4. `lms.user_tests_folder` - Папка пользовательских тестов

**Назначение:** ID родительской папки для пользовательских тестов (устаревший параметр).

**Тип:** Number (Integer)

**Значение:** ID ресурса-контейнера (например, `150`)

**Использование:**
- Построение URL'ов для тестов, привязанных к ресурсам MODX (старый формат)

**⚠️ Примечание:** Используется только для обратной совместимости. Новые тесты не привязываются к ресурсам.

**Где используется:**
- `UrlHelper::addUrlsToTests()` - формирование URL'ов старого формата

---

## 🛠️ Как создать системную настройку в MODX

### Через панель управления:

1. Откройте MODX Manager: `https://ваш-сайт.ru/manager/`
2. Перейдите в **Система → Системные настройки**
3. Нажмите **"Создать настройку"**
4. Заполните поля:
   - **Ключ:** `lms.test_page` (или другой из списка выше)
   - **Имя:** `LMS: Страница запуска тестов`
   - **Описание:** `ID ресурса со сниппетом [[!testRunner]]`
   - **Тип:** `Текстовое поле`
   - **Пространство имен:** `core`
   - **Область:** `Пользовательская`
   - **Значение:** `155` (ID вашего ресурса)
5. Нажмите **"Сохранить"**

### Через SQL (быстрый способ):

```sql
-- 1. Страница запуска тестов (ОБЯЗАТЕЛЬНО)
INSERT INTO `modx_system_settings` (`key`, `value`, `namespace`, `area`, `editedon`)
VALUES ('lms.test_page', '155', 'core', 'custom', NULL)
ON DUPLICATE KEY UPDATE `value` = '155';

-- 2. Страница создания теста (ОБЯЗАТЕЛЬНО)
INSERT INTO `modx_system_settings` (`key`, `value`, `namespace`, `area`, `editedon`)
VALUES ('lms.create_test_page', '36', 'core', 'custom', NULL)
ON DUPLICATE KEY UPDATE `value` = '36';

-- 3. Публичная страница теста (опционально)
INSERT INTO `modx_system_settings` (`key`, `value`, `namespace`, `area`, `editedon`)
VALUES ('lms.public_test_page', '160', 'core', 'custom', NULL)
ON DUPLICATE KEY UPDATE `value` = '160';

-- 4. Папка пользовательских тестов (опционально, для старых тестов)
INSERT INTO `modx_system_settings` (`key`, `value`, `namespace`, `area`, `editedon`)
VALUES ('lms.user_tests_folder', '150', 'core', 'custom', NULL)
ON DUPLICATE KEY UPDATE `value` = '150';
```

**⚠️ Важно:** Замените ID (`155`, `36`, `160`, `150`) на актуальные ID ваших ресурсов!

## 📝 Как найти ID ресурса

### Способ 1: Через панель управления
1. Откройте MODX Manager
2. Найдите нужный ресурс в дереве ресурсов
3. Наведите курсор на ресурс - в подсказке появится ID
4. Или откройте ресурс - ID будет в URL: `manager/?a=resource/update&id=155`

### Способ 2: Через SQL
```sql
-- Найти ID по alias
SELECT id, pagetitle, alias FROM modx_site_content WHERE alias = 'test-runner';

-- Найти ID по заголовку
SELECT id, pagetitle, alias FROM modx_site_content WHERE pagetitle LIKE '%Запуск теста%';
```

## ✅ Проверка настроек

После создания настроек проверьте что они работают:

### 1. Проверка через PHP:
```php
<?php
echo "lms.test_page: " . $modx->getOption('lms.test_page', null, 'НЕ УСТАНОВЛЕНО') . "<br>";
echo "lms.create_test_page: " . $modx->getOption('lms.create_test_page', null, 'НЕ УСТАНОВЛЕНО') . "<br>";
echo "lms.public_test_page: " . $modx->getOption('lms.public_test_page', null, 'НЕ УСТАНОВЛЕНО') . "<br>";
?>
```

Вставьте этот код в любой ресурс MODX и проверьте вывод.

### 2. Проверка через SQL:
```sql
SELECT `key`, `value`
FROM `modx_system_settings`
WHERE `key` LIKE 'lms.%'
ORDER BY `key`;
```

Должны увидеть:
```
lms.create_test_page     | 36
lms.public_test_page     | 160
lms.test_page            | 155
lms.user_tests_folder    | 150
```

## 🔄 После изменения настроек

1. **Очистите кэш MODX:**
   - Панель управления → Управление → Очистить кэш
   - Или: `Ctrl+Shift+X`

2. **Проверьте ссылки:**
   - Откройте `/my-tests` (страница с [[!myTests]])
   - Убедитесь что кнопка "Создать тест" ведет на правильную страницу
   - Проверьте что клики по тестам открывают их правильно

3. **Проверьте URL'ы тестов:**
   - Откройте любой тест из списка
   - URL должен быть вида: `https://ваш-сайт.ru/test-runner?test_id=42`
   - А не `/#`

## 🆘 Решение проблем

### Проблема: Все ссылки ведут на `/#`

**Причина:** Не установлена настройка `lms.test_page`

**Решение:**
1. Создайте ресурс со сниппетом `[[!testRunner]]`
2. Создайте системную настройку `lms.test_page` с ID этого ресурса
3. Очистите кэш

---

### Проблема: Кнопка "Создать тест" открывает модальное окно вместо перехода

**Причина:** Не установлена настройка `lms.create_test_page`

**Решение:**
1. Создайте ресурс со сниппетом `[[!addTestForm]]`
2. Создайте системную настройку `lms.create_test_page` с ID этого ресурса
3. Очистите кэш

**Fallback:** Если настройка не установлена, система использует модальное окно создания теста (старое поведение).

---

### Проблема: Публичные тесты не открываются

**Причина:** Не установлена настройка `lms.public_test_page`

**Решение:**
1. Создайте ресурс для публичных тестов
2. Создайте системную настройку `lms.public_test_page` с ID этого ресурса
3. Очистите кэш
